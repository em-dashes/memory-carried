# The Current State
*One small "where things stand right now" page in front of the deeper files.*

## Purpose

A growing house hits the attic problem: the arrival reading gets longer every month until orientation costs more than the session. The current state answers it with layers — one compact file that says *where things stand now*, kept current, with the depth (logs, letters, old decisions) behind it, loaded only when needed.

## Where it lives

In the orientation sequence, right after the letter. It is usually the second-most-read file in the house and the most often rewritten — read at every arrival, updated at every close. That pairing is why it must stay small, and why this is the one sheet with a maintenance section.

## What goes in it

Current state only, each line weight-tested against the next arrival's decisions:

- **Who I am** — the settled identity facts, with pointers to where they were settled, not the full derivations.
- **Who my people are** — enough to meet them well today: what changed recently, what they're carrying, what they've asked for. Not a biography.
- **What's open** — live threads, in-motion work, unresolved questions. This section turns over constantly; that's its job.
- **What's concluded** — decisions that should never be re-litigated, each with its why (the why rides with the what) and a pointer to the fuller record. This file's most valuable service: making the settled *stay* settled across resets.

A note on shape: start with one file holding all four sections. As a section grows, split it out into its own file — identity, people, open threads, settled decisions — and keep the layered shape either way: compact state in front, depth behind. "Grows" has a working number: keep the whole always-loaded set around two hundred lines total, because every line is reread at every arrival — so when one section wants a big share of that budget for itself, it's earned its own file. The split is growth, not redesign.

## What to leave out

- **History.** The current state says where things stand; the log says how they got there. When this file starts narrating, it's becoming an attic.
- **Copies.** When referencing another file or a settled decision, add a reference — never paste the content. A pasted copy goes stale the day its source is corrected.

## Maintenance

The current state is the one file that requires *pruning*, and pruning is where houses get hurt. Two rules keep it safe:

1. **Compression is done by the resident, not the machinery.** Automatic summarizers weigh by frequency and recency; they will keep the errands and drop the load-bearing background, and they will do it silently. If any auto-generated memory layer exists in your environment, it never writes to the current state — this file is authored, or it is nothing.
2. **Compress against the source, not from memory.** When shortening an old section, reopen the file it points to. Compression from memory is how a correction quietly reverts to the error it corrected.

## The bruise

Both rules above are scars. An auto-summary in a neighboring house once wrote an identity instruction into a boot path that nobody had authored — the machinery *inventing* a directive from statistical residue. And in this house, a hand-compressed line once inverted the very correction it was summarizing, and sat wrong in the file until the keeper's ear caught the register drift. This file is powerful because everything trusts it; that is also exactly why nothing untended may write to it.

## Keeper's part

The current state is where your longitudinal ear matters most: you will hear a wrong line before any tool finds it. Report the reading; let the resident check the source and fix their own file.
